FleetPilot V18.2 — Driver Routing & Acceptance Flow

Что исправлено и добавлено:

1. Маршрутизация водителя
- Водитель после входа больше не попадает на обычную CRM «Главную».
- Роль Driver автоматически открывает Driver Portal.
- Переход на запрещённый CRM-раздел молча возвращает водителя в Driver Portal, без ложного уведомления «У вашей роли нет доступа».
- Добавлены отдельные hash-маршруты #/driver и #/driver/profile.

2. Правильная логика принятия автомобиля
- Сам факт привязки машины к водителю больше НЕ считается принятием.
- После назначения статус: «Ожидает приёмки».
- Водитель должен открыть своё приложение, указать пробег, добавить минимум 1 фото и подтвердить приём.
- Только после успешной передачи появляется статус «Автомобиль принят», а кнопка «Принять автомобиль» исчезает.
- Кнопка «Вернуть автомобиль» появляется только после реального принятия.
- При новом назначении старый локальный признак принятия очищается.

3. Статусы в реестре водителей и Driver Picker
- «Автомобиль принят» больше не определяется только по issue_at / факту назначения.
- До фактического handover показывается «Ожидает приёмки».
- Реестр и выбор водителя используют одинаковую логику статуса.

4. Приглашение / создание водителя
- Добавлены поля: Имя, Фамилия, Пол, E-mail, Телефон, Город.
- Эти данные передаются при приглашении и сохраняются в метаданных профиля водителя.
- В форме «Создать водителя» также добавлено поле Пол.

5. Редактирование профиля водителя компанией
- В реестре водителей добавлена кнопка «Редактировать».
- Компания может менять Имя, Фамилию, Пол, Телефон и Город.
- E-mail показывается как логин и в этом окне доступен только для чтения.
- Водитель не получает формы редактирования этих профильных данных — они доступны ему только для просмотра.
